# LM Studio Settings — Qwen3.5-9B

Этот файл фиксирует настройки, использованные для локального запуска **Qwen3.5-9B** в LM Studio, и кратко объясняет назначение каждого параметра.

> Источник значений: текущие настройки LM Studio, показанные на скриншотах.
> Пояснения ниже — техническое описание назначения параметров.

## Model information

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| Model | `qwen/qwen3.5-9b` | Идентификатор модели в LM Studio. | Позволяет точно понимать, какая модель использовалась. |
| Model file | `Qwen3.5-9B-Q4_K_M.gguf` | Конкретный GGUF-файл модели. | Нужен для воспроизводимости benchmark и конфигурации. |
| Format | `GGUF` | Формат файла модели, используемый llama.cpp-совместимыми runtime. | Хранит веса и метаданные модели в формате, удобном для локального inference. |
| Quantization | `Q4_K_M` | 4-битная K-quant квантизация. | Уменьшает размер модели и потребление памяти ценой некоторой потери точности. |
| Architecture | `qwen35` | Архитектура модели, которую определяет LM Studio. | Runtime использует её для правильной загрузки и выполнения модели. |
| Size on disk | `6.55 GB` | Размер GGUF-файла на диске. | Помогает оценить место на SSD; это **не** равно реальному VRAM usage. |

## Context and offload

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| Context Length | `8192` tokens | Максимальное рабочее контекстное окно текущей загрузки модели. | Определяет, сколько токенов prompt + history + output модель может одновременно учитывать. Больший context увеличивает память под KV cache. |
| Model maximum context | `262144` tokens | Максимальный context, заявленный моделью. | Это теоретический предел модели, а не фактически используемый context в текущем benchmark. |
| GPU Offload | `32` layers | Количество слоёв модели, вынесенных на GPU. | Чем больше слоёв выполняется на GPU, тем обычно выше скорость и тем больше требуется VRAM. В текущем UI ползунок установлен на максимум. |

## CPU and batching

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| CPU Thread Pool Size | `12` | Число CPU-потоков, доступных llama.cpp engine. | Используется для CPU-частей inference, preprocessing и операций, не выполняющихся на GPU. |
| Evaluation Batch Size | `2048` | Логический размер batch при обработке prompt. | Больший batch может ускорять prompt processing, но увеличивает требования к памяти. |
| Physical Batch Size | `512` | Размер физического batch, реально обрабатываемого за один проход. | Позволяет разбить большой evaluation batch на более управляемые части. |
| Max Concurrent Predictions | `4` | Максимум параллельных генераций. | Полезно для API/нескольких пользователей, но конкурирующие запросы делят вычислительные ресурсы и память. |

## KV cache

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| Unified KV Cache | `Enabled` | Общий механизм управления KV cache для активных sequence/predictions. | Упрощает и потенциально повышает эффективность использования памяти при нескольких запросах. |
| Offload KV Cache to GPU Memory | `Enabled` | KV cache хранится в GPU memory, когда это возможно. | Обычно ускоряет attention при генерации, но расходует VRAM. |
| K Cache Quantization | `Disabled` | Квантизация K-части KV cache отключена. | Без квантизации расход памяти выше, но сохраняется исходная точность cache. |
| V Cache Quantization | `Disabled` | Квантизация V-части KV cache отключена. | Аналогично K cache: больше памяти, без дополнительной потери точности от quantization. |

## Attention and memory behavior

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| Flash Attention | `Enabled` | Оптимизированная реализация attention. | Обычно уменьшает память и ускоряет attention, особенно при более длинном контексте. |
| Keep Model in Memory | `Enabled` | Не выгружать модель после использования. | Уменьшает задержку повторной загрузки между запросами. |
| Try mmap() | `Enabled` | Использовать memory-mapped доступ к файлу модели. | Может уменьшить лишнее копирование данных и ускорить загрузку модели. |
| Context Checkpoints | `32` | Настройка checkpointing контекста в engine. | Используется runtime для управления состоянием контекста; точный эффект зависит от версии LM Studio/engine. |
| RoPE Frequency Base | `Auto` | Базовая частота Rotary Positional Embeddings. | Влияет на позиционное кодирование и поддержку context length. `Auto` использует значения модели/runtime. |
| RoPE Frequency Scale | `Auto` | Масштабирование RoPE. | Может использоваться для изменения эффективного context window. `Auto` сохраняет рекомендуемое поведение модели. |

## Reasoning

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| Enable Thinking | `Enabled` | Разрешает модели выполнять встроенный reasoning/thinking режим до финального ответа. | Может улучшать сложные reasoning-задачи, но обычно увеличивает количество generated tokens и latency. |
| Reasoning Budget | `Unrestricted` | Жёсткий лимит reasoning budget не задан. | Модель может использовать столько reasoning-токенов, сколько считает нужным в рамках других лимитов. |
| Reasoning Budget Message | empty | Дополнительное сообщение/инструкция для reasoning budget не задано. | Позволяет при необходимости передавать модели специальную инструкцию о reasoning. |

## Sampling

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| Temperature | `1` | Управляет случайностью распределения следующего токена. | Более низкие значения делают ответы стабильнее; более высокие — разнообразнее. |
| Top K | `20` | На каждом шаге выбор ограничивается K наиболее вероятными токенами. | Уменьшает вероятность выбора маловероятных токенов. |
| Top P | `0.95` | Nucleus sampling: используются токены, суммарная вероятность которых достигает P. | Контролирует разнообразие динамически в зависимости от распределения вероятностей. |
| Presence Penalty | `1.5` | Штрафует токены/содержимое, которое уже появлялось. | Может уменьшать повторения и стимулировать появление новых формулировок. |
| Repeat Penalty | `Disabled` | Дополнительный repeat penalty не включён. | При включении отдельно подавляет повторение уже использованных токенов. |
| Min P Sampling | `Disabled` | Minimum-P filtering отключён. | Этот фильтр отбрасывает токены с вероятностью слишком низкой относительно лучшего кандидата. |
| Seed | `Random Seed` | Фиксированный seed не задан. | Повторный запуск может давать немного разные результаты даже при одинаковом prompt. |

## Output control

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| Limit Response Length | `Disabled` | Отдельный лимит длины ответа в UI не задан. | Модель может генерировать до stop condition или ограничения context/runtime. |
| Context Overflow | `Truncate Middle` | При переполнении context LM Studio удаляет часть старого контекста из середины. | Позволяет продолжить диалог при переполнении, но часть истории будет потеряна. |
| Stop Strings | empty | Пользовательские stop sequences не заданы. | Генерация завершается по стандартным stop/EOS правилам модели. |
| Structured Output | `Disabled` | Принудительный structured/schema output не используется. | Ответ генерируется в обычном свободном текстовом формате. |

## Speculative decoding

| Setting | Value | Что это | Для чего |
|---|---|---|---|
| Speculative Decoding | `Off` | Draft model для speculative decoding не используется. | При включении маленькая draft-модель может предлагать токены большой модели и иногда ускорять generation. |

## Benchmark runtime summary

Для текущего Qwen3.5-9B Core Benchmark основной блок можно фиксировать так:

```text
Model: Qwen3.5-9B
Exact model/repository: qwen/qwen3.5-9b
Quantization: Q4_K_M
Runtime: LM Studio
Context length: 8192
GPU offload: 32 layers
Reasoning mode: Enabled, budget unrestricted
Temperature: 1
VRAM used: Not recorded
System RAM used: Not recorded
```

## Важные замечания

- `6.55 GB` — размер файла модели на диске, а не объём занятой VRAM.
- `262144` — максимальный context, поддерживаемый моделью, но benchmark запускался с `8192`.
- `GPU Offload = 32` записываем как `32 layers`. По скриншоту видно, что ползунок стоит на максимуме, но лучше не называть это `full offload`, пока runtime явно не подтвердит, что все вычислительные слои находятся на GPU.
- `VRAM used` и `System RAM used` лучше оставить `Not recorded`, если реальные значения во время benchmark не измерялись.
- Для будущих сравнений моделей желательно не менять sampling/reasoning settings между тестами без отдельной записи, иначе сравнение будет менее чистым.
